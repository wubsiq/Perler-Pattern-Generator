## 第十三轮：花纹 tile 重做（去淡出）+ 图案尺度改成"以整幅为单位"

### hh 的需求
1. 纹理还是太模糊，而且有"边界模糊"
2. 图案要尽量做完整
3. 图案尺度改成**以整幅为单位**（不是挂在豆径上）——"现在纹理有参数可调，不怎么依赖豆子了"

### ★ 诊断（先量后改，没有猜）
把 6 张图（4 素材 + 2 效果图）逐像素量化，定位到**两个独立问题**：

**① 边界模糊 = tile 的"边界淡出"在平铺后变成死带**
   - 4 张花纹 tile：边缘 13px 平均振幅只有中心的 **5.8% / 15.6% / 6.3% / 8.1%**
   - 4 张澡巾 tile（镜像分支，没有淡出）：**98%~100%** —— 差别就在这里
   - hh 那两张效果图实测：黑区逐列局部振幅中位数 25.6，但在 x=309/597/883 掉到 1.5~1.9，
     间距 287 ≈ tile 周期 256 × 截图缩放 1.12；另一张 362 = 256 × 1.41
   - 放大后能直接看到十字形无纹理带
   - **自相似性实测：4 张 tile 在 lag=128 处 RMS 差精确为 0.00** ——
     也就是说"真周期 + 整数倍平铺"本来就无缝，那份淡出保险纯属负收益

**② 模糊 = 生成端三个叠加因素**
   - 高斯 σ=3~4 写死，而单元只有 32~128px（斜纹单元才 32px 高，σ=4 直接糊穿）
   - 渐变匹配只 16 档灰阶（实测取值就是 8,24,…,248）；摆幅 145 时每档跳 18 个灰阶
     → 印记只有 16 种深浅
   - 素材是 JPEG 截图 + LANCZOS 缩放，硬边先丢一轮

**③ 尺度挂错了坐标系（hh 的第三条需求）**
   `_ironSampleLightField` 按**渲染像素 1:1** 铺 tile，而 `k = cellSize/30` 只用在程序生成层，
   没乘到光影场。后果：
   - 预览倍率 1×~4× → 豆径 20~80px → 同一个"大小 1.0×"覆盖 12.8~3.2 颗豆（差 4 倍）
   - 预览用 2800px 预算、导出用 4800px → 大图两者 cellSize 不同（实测 23 vs 30）
   - hh 那两张效果图也是：一张 tile 盖 10.7 颗豆，另一张 8.3 颗

**A. 新生成器 `tools/gen-iron-textures.mjs`（Node，替代花纹分支的 .py）**

## 第十四轮：投影参数面板 + 熔融模式下投影消失的根因修复

### hh 的需求
1. 熨烫预览里加**阴影参数**可调
2. 反馈："开了熔融边，阴影效果不知道是被遮挡了，还是停止渲染了"

### ★ 根因：不是遮挡，是几何体退化成空集

`_ironMaskToPath()` 用的是 **marching squares** —— 对每个格子按 case 表吐 1~2 条
`moveTo+lineTo`，产出的是**一堆不闭合的独立线段**。Canvas 的 `fill()` / `clip()`
都按「闭合区域」处理路径，开放线段既围不出区域也构不成裁剪环。

无头 Chrome 实测（40×40 实心方块，阈值法本身没错）：

| 调用 | marching squares | 对照（rect / 真闭合路径） |
|---|---|---|
| `fill(path)` | **0 像素** | 400 |
| `clip(path)` 后铺满 | **保留 0 像素** | 400 |

→ 熔融模式下**纹理层 / 格线层 / 光照层全部一像素没画出来，投影也是空的**。
表现就是"开了熔融边阴影就消失"。上一轮结论"熔融边是 no-op"其实还漏了一半：
底色因为走 `drawImage(geo.mask.canvas)` 所以还在，裁剪切空才让后三层集体消失。

### 修复 A：marching squares → 有向边串闭环

```
① 3×3 邻域投票（沿用原逻辑）→ inside 二值图
② 逐像素吐边界有向边，方向恒定保证「成品恒在右手边」：
     上边 TL→TR、右边 TR→BR、下边 BR→BL、左边 BL→TL
   → 外轮廓与内洞绕向天然相反，nonzero fill 直接挖洞，不用 evenodd/反向描边
③ 按起点排序建 CSR 邻接表 + 二分查找，串成闭环
   鞍点（对角相接/棋盘格）同顶点 2 条出边 → 按「右转>直行>左转>掉头」固定优先级
```

省内存的两个细节：
- 只存「终点 + 方向」，起点由 `end - dir` 反推（省一份数组）
- 用 CSR + 二分而不是 `Map<顶点, 边[]>` —— 2800² 的图有 **780 万个顶点**，
  顶点开数组会炸内存

无头六项验证：实心 fill/clip 均 896、甜甜圈 1536（洞正确挖掉）、对角相接 642、
双孤岛 288、棋盘格 **1.3ms**、空 mask 返回空路径不崩。
（与期望值的个位数差异来自 ① 的边缘侵蚀，是原有行为，非本改动引入。）

### 修复 B：投影参数面板

新增 `_IRON_SHADOW_DEFAULTS` / `_ironShadowParamSpec()` / `_ironShadowParams(state)`，
完全照熔融参数那套结构（spec 单一来源 + 默认值回填 + 「数值实时、渲染延迟」手感）：

| 参数 | 默认 | 范围 | 说明 |
|---|---|---|---|
| 浓度 opacity | 0.45 | 0~1 | 滑到 0 直接 return，短路 |
| 柔和 blur | 0.30 | 0~1.2 | 按豆径倍数，**不进 amp**（影子软硬跟豆子大小无关，只跟离桌面距离有关）|
| 横向 dx | 0.16 | -1.5~1.5 | 负值往左投 |
| 纵向 dy | 0.26 | -1.5~1.5 | 负值往上投（顶光）|
| 扩散 spread | 0.0 | 0~1 | >0 时叠 3 圈等比放大的副本，模拟半影向外爬 |

默认值刻意贴着改之前的硬编码（`0.34+0.22*amp` / `cellSize*0.30` / `0.16` / `0.26`），
所以**不开面板时的观感不变**。浓度公式改成 `opacity * (0.72+0.28*amp)`，
保留滑杆的绝对控制权 —— 滑到 0 就一定没有影子。

参数生效性（变暗总量 / 峰值 / 覆盖像素 / 质心）：
- 浓度 0 → 0/0/0（短路正确）；0.2 → 83万/8；0.45 → 186万/18；0.95 → 381万/37（单调）
- 柔和 0.02 → 覆盖 11.6万；1.1 → 覆盖 **16.4万**（越柔铺得越开）

- 纵向 -0.9 → 质心 Y 240.1；扩散=1 → 覆盖 **22.3万**、变暗总量翻倍

**★ 度量踩坑（重要）**：验投影**不能用"暗像素个数"** —— 背景 `#2a2a2a` 的 R=42 本来
就 < 60，阴影前后都被计成暗像素，差值恒为 0，看着像没渲染（第一版就踩了，
一度以为修失败）。同理**验模糊不能用"变暗总量"**（对模糊守恒）。
正确口径：浓度看总量+峰值、模糊看覆盖面积、偏移看质心、扩散看覆盖+总量。
