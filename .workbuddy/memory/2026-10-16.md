# 2026-10-16

## 第十三轮：花纹 tile 重做（去淡出）+ 图案尺度改成"以整幅为单位"

### hh 的需求
1. 纹理还是太模糊，而且有"边界模糊"
2. 图案要尽量做完整
3. 图案尺度改成**以整幅为单位**（不是挂在豆径上）——"现在纹理有参数可调，不怎么依赖豆子了"

### ★ 诊断（先量后改，没有猜）
把 6 张图（4 素材 + 2 效果图）逐像素量化，定位到**两个独立问题**：

**① 边界模糊 = tile 的"边界淡出"在平铺后变成死带**
   - 4 张花纹 tile：边缘 13px 平均振幅只有中心的 **5.8% / 15.6% / 6.3% / 8.1%**
   - 4 张澡巾 tile（镜像分支，没有淡出）：**98%~100%** —— 差别就在这里
   - hh 那两张效果图实测：黑区逐列局部振幅中位数 25.6，但在 x=309/597/883 掉到 1.5~1.9，
     间距 287 ≈ tile 周期 256 × 截图缩放 1.12；另一张 362 = 256 × 1.41
   - 放大后能直接看到十字形无纹理带
   - **自相似性实测：4 张 tile 在 lag=128 处 RMS 差精确为 0.00** ——
     也就是说"真周期 + 整数倍平铺"本来就无缝，那份淡出保险纯属负收益

**② 模糊 = 生成端三个叠加因素**
   - 高斯 σ=3~4 写死，而单元只有 32~128px（斜纹单元才 32px 高，σ=4 直接糊穿）
   - 渐变匹配只 16 档灰阶（实测取值就是 8,24,…,248）；摆幅 145 时每档跳 18 个灰阶
     → 印记只有 16 种深浅
   - 素材是 JPEG 截图 + LANCZOS 缩放，硬边先丢一轮

**③ 尺度挂错了坐标系（hh 的第三条需求）**
   `_ironSampleLightField` 按**渲染像素 1:1** 铺 tile，而 `k = cellSize/30` 只用在程序生成层，
   没乘到光影场。后果：
   - 预览倍率 1×~4× → 豆径 20~80px → 同一个"大小 1.0×"覆盖 12.8~3.2 颗豆（差 4 倍）
   - 预览用 2800px 预算、导出用 4800px → 大图两者 cellSize 不同（实测 23 vs 30）
   - hh 那两张效果图也是：一张 tile 盖 10.7 颗豆，另一张 8.3 颗

### 改动

**A. 新生成器 `tools/gen-iron-textures.mjs`（Node，替代花纹分支的 .py）**
本机没有 python 解释器，所以用 Node 重写；JPEG 素材借 PowerShell/System.Drawing 转一次 PNG。
平铺策略按素材**实测**有没有周期分两支（roll 打分，.diag/probe.js）：

| 素材 | roll x/y | 结论 | 策略 |
|---|---|---|---|
| S 波 | 0.23 / 0.21 | 真周期 132.25×66 | 小数锁相 + 整数倍平铺（接缝 0.10/0.03）|
| 斜纹 | 0.99 / 0.99 | 两轴都无周期 | 周期+切缝联合优化 |
| 鱼鳞 | 0.95 / 0.57 | 仅 Y 可靠 | 同上 |
| 青海波 | 0.79 / 0.91 | 两轴都不干净 | 同上 |

其它改动：不做淡出；单元按原分辨率保留（不压到 128/256）；高通/高斯全部走 **wrap 边界**
（原来 reflect 会破坏周期性，等于在 tile 边界又造一条缝）；σ 3~4 → **1.0**；
量化 16 → **65 档**（步长 4，且 128 可精确表示，中性点不再被推到 136）。

**★ 镜像方案试过并否决**：斜纹变菱形万花筒、鱼鳞变曼陀罗 —— 这几个素材有方向性，
镜像会毁掉方向。改用「周期 + 切缝位置联合优化」：只挪"从素材哪里切、切多大"，
目标函数 = **高通之后的接缝跳变 / 场 RMS**（≈接缝可见度）。

**B. 运行时（mixins/IronPreviewMixin.js）**
1. `_ironLightTile` 不再把 tile 强行拉成 256×256（花纹 tile 是非正方形/非 256 的）
2. 新增 `_ironTexAnchoredGeom()` —— 尺度锚点：
   - `art`（矢量花纹）：1.0× ⇒ **作品长边跨过 meta.baseTiles 个 tile**，与预览倍率、
     导出尺寸都无关 → 滑杆调好的值在任何地方都成立
   - `bead`（澡巾等实物肌理）：按豆径（一颗豆上的颗粒数不随倍率变）
3. tiles.js 的 META 增 `anchor` / `baseTiles`

### 验证（无头 Chrome 跑真实渲染代码，`.diag/verify.html`）

|---|---|---|

| 周期/整幅宽 = 1× / 1.5× / 2× / 4× / 导出 | 随倍率漂移 | **0.138 / 0.139 / 0.139 / 0.139 / 0.139**（恒定）|

不设实例状态会静默回落到 list[0]（澡巾1）。
